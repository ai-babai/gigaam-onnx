# GigaAM-v4 runtime compatibility

The packaged CTC, offline RNN-T and streaming RNN-T clients ran on **macOS 15.8.1 arm64** and **Ubuntu 26.04.1 x86_64** with ONNX Runtime 1.23.2 (CPU). We compared one Russian and one English FLEURS recording using identical model and audio bytes. Both offline clients returned identical transcripts across platforms. Streaming produced text before flush on both recordings. Its formatted Russian transcript contained a reproducible one-character difference between platforms; its raw Russian and both English outputs matched.

The same CTC graph also ran through **sherpa-onnx 1.13.2** and the **transcribe-rs 0.3.11** GigaAM loader used by AutoSubs. On Linux these two integrations used ONNX Runtime 1.24.4 with three CPU threads. On the two comparison recordings, each native loader matched its Mac counterpart exactly. The Rust example used its locked dependency graph with only the thread count set to three.

**Python `onnx-asr` 0.12.0** lacks a stock loader for these GigaAM-v4 packages on both platforms. Pointing its v3 CTC loader at renamed files changes the frontend. In a 32-recording Mac comparison only 24 transcripts matched the bundled client. Use the included ONNX Runtime clients, or one of the verified CTC integrations.
